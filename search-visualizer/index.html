Linear Search｜順序搜尋法

從第一個資料開始，一個一個往後找，直到找到目標為止。

💭 就像在一排人裡面找朋友，從第一個人開始一個一個問：「你是我要找的人嗎？」

演算法程式碼

for (let i = 0; i < arr.length; i++) {
// ① 從頭開始掃描
  if (arr[i] === target) {
// ② 檢查目前資料是不是目標
    return i;
// ③ 找到了，回傳位置
  }
// ④ 不是就繼續往下找
}
// ⑤ 掃描完畢
return -1;
// ⑥ 全部都不是，回傳 -1

💡 學習重點

  • 從頭開始一個一個找
  • 不需要資料排序
  • 資料越多，可能要找越久（最壞 O(n)）

Binary Search｜二分搜尋法

二分搜尋會先看中間的數字，再決定答案在左邊還是右邊。

💭 就像查字典，不會從第一頁一頁一頁找，而是先翻到中間，再決定往前還是往後。

演算法程式碼

let left = 0;
// ① 搜尋範圍左界
let right = arr.length - 1;
// ② 搜尋範圍右界
while (left <= right) {
// ③ 範圍還存在就繼續
  const mid = Math.floor((left + right) / 2);
// ④ 找出中間位置
  if (arr[mid] === target) {
// ⑤ 中間就是目標？
    return mid;
// ⑥ 找到了！
  }
  if (arr[mid] < target) {
// ⑦ 目標在右半邊？
    left = mid + 1;
// ⑧ 排除左半邊
  } else {
// ⑨ 目標在左半邊
    right = mid - 1;
// ⑩ 排除右半邊
  }
}
return -1;
// ⑪ 範圍空了，找不到

💡 學習重點

  • 必須使用已排序資料
  • 每次查看中間位置
  • 每次可以排除一半資料
  • 資料很多時非常有效率（O(log n)）

搜尋法比較次數特色

二分搜尋因為每次都能排除一半資料，所以資料很多時通常可以更快找到答案。

⏱ 搜尋演算法複雜度

先用生活化的方式感受，再看公式。

搜尋法最佳平均最壞
順序搜尋O(1)O(n)O(n)
二分搜尋O(1)O(log n)O(log n)

O(n) 是什麼感覺？假設有 100 個人要找，你可能要一個一個問，最壞可能問到第 100 個人。資料多一倍，可能就要多找一倍的時間。

O(log n) 是什麼感覺？假設有 100 個資料，第一次看完中間切成兩半，剩 50；再切一半剩 25；再切剩 12……資料一直砍一半，所以不需要一個一個找。二分搜尋每找一次，就把「不用看的資料」砍掉一大半。

兩種方法的差別：

順序搜尋：👀 → 👀 → 👀 → 👀 → 👀 → 🎯（一個一個找，最壞要看完所有資料）

二分搜尋：❌❌❌❌｜👀｜❌❌❌❌ → 再縮小 → 🎯（每次直接砍掉一半不用看的資料）
