Linear Search｜順序搜尋法

「一個一個檢查。」

從第一個資料開始，一個一個往後找。不需要排序，但最壞情況可能要檢查所有資料。

演算法程式碼

for (let i = 0; i < arr.length; i++) {
// ① 從頭開始掃描
  if (arr[i] === target) {
// ② 檢查目前資料是不是目標
    return i;
// ③ 找到了，回傳位置
  }
// ④ 不是就繼續往下找
}
// ⑤ 掃描完畢
return -1;
// ⑥ 全部都不是，回傳 -1

💡 學習重點

  • 從頭開始一個一個找
  • 不需要資料排序
  • 資料越多，可能要找越久（最壞 O(n)）

演算法程式碼

let left = 0;
// ① 搜尋範圍左界
let right = arr.length - 1;
// ② 搜尋範圍右界
while (left <= right) {
// ③ 範圍還存在就繼續
  const mid = Math.floor((left + right) / 2);
// ④ 找出中間位置
  if (arr[mid] === target) {
// ⑤ 中間就是目標？
    return mid;
// ⑥ 找到了！
  }
  if (arr[mid] < target) {
// ⑦ 目標在右半邊？
    left = mid + 1;
// ⑧ 排除左半邊
  } else {
// ⑨ 目標在左半邊
    right = mid - 1;
// ⑩ 排除右半邊
  }
}
return -1;
// ⑪ 範圍空了，找不到

💡 學習重點

  • 必須使用已排序資料
  • 每次查看中間位置
  • 每次可以排除一半資料
  • 資料很多時非常有效率（O(log n)）

⏱ 搜尋演算法複雜度

先用生活化的方式感受，再看公式。

搜尋法最佳平均最壞
順序搜尋O(1)O(n)O(n)
二分搜尋O(1)O(log n)O(log n)

💡 為什麼？

順序搜尋 O(n)：資料增加，可能就要多檢查很多元素。100 個資料，最壞可能要找 100 次。

二分搜尋 O(log n)：每一次都排除大約一半的資料。100 個資料，約 7 次就能縮小到很小的範圍。

✂️ 每一步都砍掉一半
64→32→16→8→4→2→1

n → n/2 → n/4 → n/8 … 這就是 O(log n) 的意思。
